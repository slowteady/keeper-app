# PRD — 실종·분실 유저 작성(Phase 2) + 실종 전단(포스터) 생성

> 상태: 확정 (2026-07-14)
> 입력 백로그: `docs/backlog/features/05-missing-ugc-poster.md`
> 선행: 실종 Phase 1(공공 열람, `docs/archive/community-missing/`) · 포스터 파이프라인(입양공고, `docs/archive/poster-template-share/`)
> 제외: AI 폼 prefill → 후속 `05-ai-poster-prefill`

## 1. 개요

내 반려동물이 사라졌을 때 keeper에서 **직접 실종글을 올리고**, 데이터로 **실종 전단(포스터)을 즉시 생성**해 오프라인·SNS로 확산한다. 기존 공공 실종 열람(읽기 전용)에 유저 작성(UGC)을 더해 실종·분실 영역을 완성한다. 이미 동기화 중인 유기동물 공고와 **룰 기반 발견매칭**으로 재회 가능성을 높인다.

## 2. 문제 (Problem)

- Phase 1은 공공 실종 데이터를 **읽기만** 한다. 정작 내 아이 실종 시 **올릴 수단이 없다.**
- 실종 확산의 핵심 수단인 **전단을 손으로 만들어야** 한다(디자인 부담·시간).
- 유실동물과 유기동물 공고가 **서로 격리**돼, 보호소에 이미 들어온 내 아이를 놓친다.
- keeper 정체성(정보·연결 플랫폼)의 대표 사례인데 진입점이 비어 있다.

## 3. 목표 / 비목표

### Goals

- 로그인 유저가 실종/분실글을 **작성·수정·삭제·해결처리**한다.
- 실종글 데이터로 **실종 전단**을 생성·다운로드·공유한다.
- 실종글 상세에서 **유사 유기동물 공고**("이 아이일 수 있어요")를 룰 교차로 제안한다.
- 공공 실종글과 유저 실종글을 **하나의 실종 목록**에서 매끄럽게 본다.
- 연락처 PII는 기존 공공 실종의 **contact 엔드포인트 패턴**을 그대로 따른다.

### Non-Goals (이번 제외)

- **AI 사진 발견매칭**(Petco식) — 비용·인프라 과함. 룰 교차로 대체.
- **AI 폼 prefill**(이미지→폼) — `05-ai-poster-prefill` 후속.
- **매칭 푸시 알림** — 관심알림 인프라 재사용해 후속.
- **지역 알림 broadcast망**(PawBoost/FB) — 구축 범위 밖.
- **인스타 자동/반자동 발행** — 작성자 다운로드+본인 공유. 어드민 반자동은 후속.
- **앱내 1:1 채팅** — 미보유 인프라, 별도 주제. 연락=전화(게이트)+댓글.
- **소스 뱃지 구분 UI** — 둘 다 연락 가능해 실익 작음. 통합 노출.

## 4. 대상 사용자

- **실종 당사자**: 내 아이를 잃은 보호자. 즉시 널리 알리고 제보받고 싶다.
- **제보자/목격자**: 근처에서 본 동물을 알려주려는 이웃. 댓글로 제보.
- **입양/구조 관심 유저**: 실종 목록을 훑으며 발견 시 연결.

## 5. 사용자 시나리오

1. 보호자가 실종글 작성(사진·품종·특징·실종일시·장소지도·보상·전화공개 여부) → 게시.
2. 상세에서 "실종 전단 만들기" → 전단 이미지 생성 → 다운로드/카톡·인스타 공유.
3. 상세 하단 "이 아이일 수 있어요"에 유사 유기동물 공고 노출 → 탭해 확인.
4. 이웃이 댓글로 "OO동에서 봤어요" 제보, 로그인 후 전화 버튼으로 연락.
5. 재회 성공 → 작성자 "찾았어요" 처리 → 카드 dim+칩, 상세 배너.

## 6. 기능 요구사항

### P0

- **FR-1 실종글 CRUD**: 작성/수정/삭제. 필드 = 사진(필수 다중)·이름?·품종·성별?·색/특징·실종일시·실종장소(지도 좌표+주소)·보상?·연락전화?·전화공개 토글(isPhonePublic). `PostType.MISSING` + `PostMissing`.
- **FR-2 통합 목록**: 공공(`LostAnimal`) + 유저(`PostMissing`) 실종글을 한 리스트로(뱃지 없음). 실종일/최신 정렬, 커서 페이지네이션.
- **FR-3 연락(contact) PII 패턴**: 목록/상세 payload에 번호 비노출(`hasContact`만). 실제 번호는 `GET /missing/:id/contact`(로그인 게이트). 비공개(isPhonePublic=false)·번호없음은 `hasContact=false`.
- **FR-4 제보 = 댓글**: `PostComment`(대댓글 포함) 재활용. 별도 목격 폼 없음.
- **FR-5 해결(찾음) 처리**: 작성자만 `status=RESOLVED` 토글. 목록 카드 "찾음" 칩 + dim 오버레이, 상세 상단 배너. 삭제·숨김 아님.
- **FR-6 실종 전단 생성**: 상세 "실종 전단 만들기" → 실종 JSX 템플릿 렌더(6요소: LOST 헤드라인·사진·특징·최종목격·연락·보상) → R2 캐시 → 다운로드/공유. `GET /posters/missing/:id`.
- **FR-7 발견매칭**: 상세 하단 "이 아이일 수 있어요" — `abandonment` 룰 교차(품종·지역·발견일 ≥ 실종일). 후보 카드 N개, 없으면 미노출.
- **FR-8 신고/모더레이션**: `Post` 상속으로 신고·블라인드(`isHidden`) 그대로.

### P1

- 전단 종별 레이아웃 미세 조정(개/고양이/기타).
- 해결 글 "가족을 찾았어요" 성공 표시 강화.

### P2 (후속)

- 매칭 푸시 알림(관심알림 재사용), 오래된 글 체크인 리마인더(bump/다운랭크), AI prefill, 인스타 반자동.

## 7. UX / 흐름 (개요)

- 진입: 기존 `(untabs)/missing/` 실종 탭. 목록 우하단 "글쓰기" FAB(커뮤니티 패턴 재활용).
- 작성 폼: 개인입양 글쓰기 폼 구조 재활용(accordion·이미지 업로드) + `location-bottom-sheet`(카카오 주소→좌표) + 지도 표시(`shelter-map` 네이버맵).
- 상세: 사진 캐러셀 → 특징/실종정보 → (해결 시 배너) → 발견매칭 섹션 → 전단 만들기 → 댓글(제보). 전화공개 시 로그인 게이트 통과 후 전화 CTA.
- 상태 시각: 기존 공고 종료(마감/입양완료) 카드 dim+칩 패턴 재활용.

## 8. Backend Impact (keeper-backend — 영향 범위만)

- **schema**: `PostType`에 `MISSING` 추가. **`PostMissing`** 신규 모델(`postId` FK, 품종/색특징/실종일시/lat·lng·address/보상?/contactPhone?/isPhonePublic/status). 마이그레이션 신규(현재 최신 `20260714053540_add_comment_reply_to_user` 다음 +1 예약).
- **모듈**: `missing`(또는 community 확장) — 작성/수정/삭제/해결 mutation, 통합 목록 조회(LostAnimal ∪ PostMissing), `GET /missing/:id/contact`(로그인 게이트), 발견매칭 룰 쿼리.
- **poster**: `PosterSource`에 실종 variant(discriminated union) + `toPosterSource(PostMissing)` 매퍼 + 실종 템플릿 JSX + `GET /posters/missing/:id`. 렌더 엔진(satori+resvg)·R2 `UploadService`·폰트·`posterKey`·캐시 재사용.
- **재활용**: `PostComment`·`PostReport`·`isHidden` 상속. 이미지 업로드 presigned R2.

## 9. 성공 지표

- 실종글 작성 수 / 주.
- 전단 생성·공유 수 / 실종글.
- 해결(찾음) 처리 비율(재회 대리 지표).
- 발견매칭 후보 노출→탭 전환율.
- (PII 준수: 번호 payload 노출 0건, 분석 이벤트에 전화·이메일 미포함.)

## 10. ADR / 컷한 옵션

- **ADR-1 소스 뱃지 컷, 통합 노출**: 공공·유저글 **둘 다 연락 가능**(공공은 `callTel not null` 필터 + contact 엔드포인트). 구분 실익 작아 통합. 제보/전단 가능 여부는 상세에서 자연 구분.
- **ADR-2 전화 = 기존 공공 contact 패턴 미러링**: 신규 노출 스킴 발명 대신, 번호는 payload 비노출 + `contact` 엔드포인트 + 필터. 로그인 게이트로 스팸 완화. `isPhonePublic` = `hasContact` on/off 스위치. keeper PII 패턴 일관.
- **ADR-3 `Post` 인프라 상속(`PostType.MISSING`+`PostMissing`)**: 신고·댓글·블라인드 재활용. 표면(실종 탭)과 저장 분리 — IA상 커뮤니티 아님 유지.
- **ADR-4 발견매칭 = 룰 교차, AI 컷**: 이미 동기화된 `abandonment` 룰 교차로 저비용 차별화. AI 사진매칭(Petco)은 1인 운영 과함.
- **ADR-5 전단 = 작성자 다운로드+본인 공유**: 실종글은 개인 UGC라 운영자 자동발행 주체 애매. 인스타 반자동은 후속.
- **ADR-6 찾음 = 상태 칩+배너, 삭제 아님**: 재회 서사 보존(keeper "한 마리라도 더" 정서), 기존 공고 종료 UI 패턴 일관.
