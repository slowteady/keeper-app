# 운영 콘솔 (Admin Console)

> 작성일: 2026-06-04
> 상태: 백로그 (P1, 출시 후). 단 **신고 처리**는 출시 직후 운영에 필요(정보통신망법) → 최소 형태라도 우선.
> 여러 기능에서 파생되는 admin 요구를 한 곳에 모음. [[release-plan]] §9 "신고 운영 주체" 미결의 귀결점. 운영 인프라 흐름은 [[service-ops-infra]].

---

## 1. 형태 (방향 결정됨)

- **관리 화면 = 별도 웹** — 공지·신고 처리·운영 플래그 조작.
- **알림 수신 = keeper 앱 admin 계정 push** — 신고 접수 등 운영 이벤트를 admin 폰으로. (`service-ops-infra` §3)
- 채널 분리: _조작은 웹, 실시간 인지는 앱._
- 인증: `user.role`(admin) + 보호 라우트. (현재 user 에 role 컬럼 없음 → 도입 필요)

---

## 2. 기능 목록

### 출시 직후 필요 (법적·운영 필수)

| 기능                  | 데이터 소스                            | 비고                                                                                              |
| --------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------- |
| **신고 처리**         | `post_report`, `comment_report`        | 목록 + 처리(`handledAt`/`handledAction`: 삭제·임시조치·기각) + 양 당사자 통지. 정보통신망법 §44-2 |
| **콘텐츠 모더레이션** | `content_moderation_log`, `user_block` | 모더레이션 로그 조회, 사용자 제재·차단                                                            |

→ 출시엔 **최소 형태**(보호된 API + 간단 화면, 또는 한시적으로 DB 도구). 본격 웹은 P1.

### 운영 (당분간 도구로 대체 가능)

| 기능            | 데이터 소스  | 비고                                                                                                                                         |
| --------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **운영 플래그** | `app_config` | 점검 on/off·메시지, ios/android min·latest version, store URL. **지금은 Prisma Studio/SQL 로 충분 → P1 에 GUI** ([[service-ops-infra]] §1·2) |
| **공지 관리**   | `notice`     | 작성·수정·삭제                                                                                                                               |

### 후순위

- **유저 관리** — `role` 부여, 제재 이력, 탈퇴 사유 집계
- **입양 후기 큐레이션** — 홈 노출 후기 선정 (product-roadmap F-09)
- **통계 대시보드** — 가입·공고·신고·입양 신청 수 등

## 3. 우선순위
