## 2. 구현 순서 (자연스러운 흐름)

**기반 → 핵심 기능 → 부가 → 운영·출시** 순. 아래로 갈수록 앞 단계에 의존.

| Phase            | 작업                                                                                                         | 왜 이 순서                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| **0. 기반**      | ① Railway 전환(EC2 무중단) → ② 로그인/회원 → ③ 강제 업데이트 게이트                                          | 백엔드·인증은 모든 유저 기능의 전제. 게이트는 빌드에 심어야 소급 가능(가장 먼저 빌드 레벨) |
| **1. 핵심**      | ④ 프로필 기본(+탈퇴 법규 점검) → ⑤ 개인입양 MVP → ⑥ 커뮤니티 입양생활·Q&A → ⑦ 신고/차단                      | 로그인 위에 얹힘. 신고/차단은 UGC(개인입양·커뮤니티) 다음                                  |
| **2. 부가**      | ⑧ 다차원 필터                                                                                                | 기존 공고에 부착, 독립 → 아무 때나 병렬 가능                                               |
| **3. 운영·출시** | ⑨ 점검 모드 → ⑩ expo-updates OTA 채널 → ⑪ 에러 모니터링(Sentry) 재셋업 → ⑫ 출시 전 QA(법규 게이트) → 🚀 출시 | 운영 스위치·모니터링 정비 후 QA, 마지막 출시                                               |

## 4. 인프라·운영 (병행)

- **Railway 백엔드 전환** — 운영 중 EC2(공공데이터 제공) 유지하며 로그인·커뮤니티 신규를 Railway로. `service-ops-infra.md` 참조.
- **운영 3종 (이번 출시 P0)** — 역할 분담이 핵심:
  - **점검 모드** = 서버 점검/장애 시 _진입 차단_ (닫을 수 없는 화면)
  - **강제 업데이트 게이트** = 네이티브·호환 깨짐 시 _구버전 차단_ → 스토어 유도 (soft/hard)
  - **expo-updates OTA** = JS/에셋 _무중단 핫픽스_ (강제 차단은 못 함 — 그래서 게이트와 별개로 둘 다 필요)
- **에러 모니터링(Sentry)** — ✅ **코드 wiring 완료(2026-06-14)**: `@sentry/react-native ~7.2.0`, metro `getSentryExpoConfig`(소스맵), expo 플러그인(org/project·자동업로드), `Sentry.init`(dsn=env·prod-only·env분리·PII off)+`Sentry.wrap`, `logger.error→captureException` funnel(ErrorBoundary/mutation/interceptor 포섭), user context(로그인 set/로그아웃 clear), 네비게이션 계측(`reactNavigationIntegration`+expo-router `useNavigationContainerRef`). 재귀 BP 재검수 통과. **대기**: 기존 프로젝트 DSN 재활용 + env(`EXPO_PUBLIC_SENTRY_DSN`/빌드용 `SENTRY_ORG`·`SENTRY_PROJECT`·`SENTRY_AUTH_TOKEN`) + 새 빌드.
- **알림 시스템(push 인프라 + 인앱) = 이번 출시 P0** (2026-06-14 승격). 소비자: 운영자 push(새 신고) · 사용자 통지(§44-2) · 마감 D-day. admin 콘솔=웹, 운영자도 앱 설치해 push 수신. `00-notification-system.md` 참조.
- 착수 시 expo-updates(EAS Update) `runtimeVersion`·채널·롤백 전략은 공식 docs(context7) 확인 후 셋업.
