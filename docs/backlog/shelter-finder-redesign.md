# 보호소 찾기(목록) 화면 재설계

- **상태**: 발산 완료 (방향 확정, design 대기)
- **일자**: 2026-06-02

## 배경 / 문제

현재 보호소 목록(`app/(tabs)/shelter`)은 **검색바 + 거리 카운트 + 지도 + 카드 리스트** 4요소가 한 화면에 평면적으로 쌓여 위계가 산만하고, 다음 문제가 있다.

1. **검색 인디케이터 버그** — 검색하면 거리 카운트 자리에 "검색 결과 N곳" 표기. 그런데 X(클리어)는 텍스트만 비우고 검색 모드를 해제(거리 카운트 복원)하지 않음. 백스페이스로 직접 지워도 마찬가지.
2. **거리 카운트(1/5/10/30km)** 역할 불명확 — 읽기 전용 표시인지 거리 필터인지 모호.
3. **"현 지도에서 검색" 버튼** 마찰 — 지도 이동마다 버튼을 눌러야 목록 갱신.
4. **검색(보호소명/주소) ↔ 위치설정(kakao 주소)** 역할 중복.
5. **지도 마커 라벨 가독성** — `caption` 11px, `color` 미지정(네이버 기본 회색), 밀집 시 겹침 + 구분 약함.

## 재설계 방향 (확정)

> 핵심 통찰: **검색을 "지도 위치 이동"으로, 범위를 "viewport"로 재정의**하면 "검색 모드 ↔ 거리 카운트 모드" 분기 자체가 사라져 1·2·3·4번 문제가 구조적으로 동시 해소된다.

1. **viewport 자동 로드** — "현 지도에서 검색" 버튼 제거. 지도 idle(debounce ~600ms) 시 보이는 영역의 보호소를 자동 fetch. NN/g 권고대로 **배경 업데이트 + 현재 선택/바텀시트 상태는 유지**(전체 리셋 금지). 보호소 333개로 데이터가 희소해 자동 로드 API 비용 낮음.
2. **바텀시트 드래그** (Airbnb 패턴) — 지도 전체화면 + 하단 바텀시트(2~3단계 snap)에 카드 리스트. 마커 탭 → 해당 카드로 snap + 하이라이트, 카드 스크롤/선택 → 마커 하이라이트 (양방향 동기화). 지도 컨텍스트를 잃지 않으면서 목록 탐색.
3. **거리 카운트 제거** — viewport가 곧 범위이므로 1/5/10/30km 카운트 불필요. 지도 줌/이동으로 범위 조절. (이 분기 제거가 인디케이터 버그의 근본 해소)
4. **검색 = 지도 위치 이동** — 주소/지역 검색 → 지도가 그 좌표로 이동 → viewport 자동 로드가 보호소 표시. 검색 결과 = viewport 결과로 통합. 위치설정 버튼과 역할 통합. (검색 모드/빈 입력 복원 같은 상태 분기 불필요)
5. **마커 라벨 가독성** — 약칭 버블(시설명 앞 N자) 또는 `color`+`haloColor` 강화, 서울·경기 밀집 구역 클러스터링(줌 레벨 ≤ 12). 선택 마커 색 강조 + 나머지 축소(Airbnb).
6. **카드 정보** — 이름 + 거리 + **오늘 운영 여부**(공공데이터 운영시간 활용, 데이터 이미 보유). `ShelterCard` ↔ `HomeShelterCard` 인터페이스 통일 검토.

## 이번 발산에서 결정된 것

| 항목          | 결정                      |
| ------------- | ------------------------- |
| 지도 + 리스트 | 바텀시트 드래그 (Airbnb)  |
| 거리 카운트   | 제거 (viewport로 대체)    |
| 검색          | 지도 위치 이동으로 재정의 |
| 로드 방식     | viewport 자동 (버튼 제거) |

## 컷한 옵션 (사유)

- **"현 지도에서 검색" 버튼 유지** — 사용자가 버튼 제거를 원함. 부동산처럼 데이터 밀도/API 비용이 큰 경우엔 버튼이 안전하나, 보호소 333개는 희소해 자동 로드로 충분.
- **탭 전환(야놀자)** — 구현은 단순하나 지도 보면서 목록을 못 봄. 바텀시트가 컨텍스트 유지에서 우월.
- **상하 분할(직방)** — 지도 높이가 절반으로 줄어 지도 가독성 저하.
- **거리 필터 칩(배민식)** — viewport가 범위를 대체하므로 칩 불필요.
- **검색 X 클릭만 모드 해제** — 백스페이스 직접 삭제를 못 잡음. + viewport 통합으로 검색 모드 개념 자체가 사라져 불필요.
- **검색 보호소명 필터 유지** — 위치 이동 재정의가 더 단순하고 위계 명확.

## 레퍼런스 BP

- **Airbnb** — viewport 자동 로드 + 바텀시트 + 마커↔카드 양방향 동기화. keeper 희소 데이터에 직접 적합. ([Airbnb Eng](https://airbnb.tech/ai-ml/improving-search-ranking-for-maps/))
- **NN/g** — 모바일 지도 자동 로드는 "배경 업데이트 + 선택 항목 유지"일 때만 권장. ([NN/g](https://www.nngroup.com/articles/mobile-maps-locations/))
- **카카오맵 / 네이버지도** — 밀집 구역 마커 클러스터링. ([Kakao](https://apis.map.kakao.com/web/sample/basicClusterer/) · [Naver](https://navermaps.github.io/maps.js.ncp/docs/tutorial-marker-cluster.example.html))
- **야놀자** — 마커 텍스트 버블 → 보호소명 약칭 응용.
- **(반면교사) Petfinder** — 지도 없는 리스트 중심은 "우리 동네" 공간 감각이 없어 보호소 탐색에 부적합.
