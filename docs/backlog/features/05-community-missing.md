# 커뮤니티 "실종분실" 탭 — 실종신고 공고 게시판

> 상태: 발산 완료. **2026-07-08 재정립** — lossInfo 응답 실검증으로 [Q7] 뒤집음(공공 데이터 채택) + 범위 Phase 1/2 분할 + **배치 재검토(커뮤니티 아님)**. prd/design/spec 산출 완료, /be 대기.

## 배치 재검토 (2026-07-08) — 커뮤니티 폐기

제목의 "커뮤니티 탭" 전제는 **폐기**. 근거 3중 수렴: ① keeper는 커뮤니티에서 공고를 빼내 QnA 소통 전용화(TabView 제거)했고, ② 외부 BP 대세가 실종=소통과 분리된 독립 열람 섹션(포인핸드 등 5/6), ③ 하단탭 3~5 상한이라 6번째 금지. → 실종은 **배치 무관 독립 화면**으로 구현하고 **진입점(홈 히어로 유력)은 얇은 스왑 레이어로 보류**. Phase 2 유저 작성이 붙으면 탭 승격(슬롯 확보). 상세는 `docs/design/05-community-missing.md` §2.

## Phase 분할 (2026-07-08)

- **Phase 1 — 공공 실종 데이터 파이프라인 + 열람** ← **이번 트랙**. data.go.kr 분실동물(lossInfo) 배치 동기화 → 비-PII 저장 → **독립 실종 화면(1컬럼 목록/상세)** + 공식 채널 인계. 유저 작성 없음.
- **Phase 2 — 유저 실종/분실 글 작성** — 별도 피처로 개발(작성 폼·위치 입력·제보 댓글 루프·찾았어요 토글). 아래 [Q1]~[Q6] 결정은 Phase 2 입력으로 보존. Phase 1의 공공 글과 앱 목록에서 합류.

## 배경

보호자가 잃어버린 동물을 찾기 위해 올리는 실종신고 공고 게시판. 커뮤니티 3탭(개인입양/실종분실/궁금해요) 중 가운데. 현재 탭 껍데기만 존재(빈 list + globalToast 플레이스홀더), 백엔드 엔티티·문서 없음.

## 확정된 결정

- **[Q1 확정] 분실 공고만** — 보호자가 "잃어버렸어요" 공고 작성. 목격/제보는 **그 공고의 댓글**로. 양방향 글(목격 별도 글)·매칭은 컷(초기 규모엔 과함, YAGNI).
- **[Q2 확정] 위치 = 지도 핀 + 좌표 저장** (완성도 높은 안) — 입력은 개인입양 `LocationBottomSheet`(카카오 주소검색→좌표) 재활용, 표시는 보호소 네이버맵 컴포넌트(`entities/shelter/ui/shelter-map.tsx`) 재활용. 좌표 컬럼 추가 + 상세화면 핀 표시. 반경 슬라이더는 나중.
  - spec 확인 필요: 카카오 Geocode 좌표(WGS84)가 네이버맵에 그대로 꽂히는지.
- **[Q3 확정] 해결 상태 = 배지 + 흐림 + 잔류** — "찾았어요" 토글 → "찾았어요" 배지 + 흐림 처리 + 미해결글 아래로 이동(목록 잔류). 미해결 필터로 숨김. 사유: 완전제거는 온기 손실(가족 매칭 정체성), 잔류+필터가 노이즈 제거 + 성공 사례 둘 다 잡음. (A 완전제거 / C 별도탭 컷)
- **[Q4 확정] 실종 일시 = 날짜 + 시간** — datetime 입력. 날짜 필수 + 시간 선택(보호자가 시각 모를 수 있음). 미래 날짜 차단. (spec: date/time picker 컴포넌트 유무 확인)
- **[Q5 확정] 정렬·필터 = 최신순 + (동물 종류 + 미해결)** — 정렬 최신순 단일. 필터는 동물 종류 ButtonGroup(QnA 패턴 재활용) + "찾는 중만" 토글. 지역 필터는 좌표만 저장해두고 글 쌓인 뒤(YAGNI).
- **[Q6 확정] 알림 = MVP 제외** — 반경 푸시는 초기 사용자 적어 가치 낮음 + 푸시 인프라 부담. **알림은 별도 기능으로 후속 독립 구현** 예정 (실종 전용 아님).
- **[Q7 재확정 — 뒤집음] 외부 공공 데이터 = data.go.kr 분실동물 API(lossInfo, 15141910) 채택** (2026-07-08 응답 실검증). 2026-06-30 컷의 핵심 근거 **"사진 없음"이 반증됨** — 실호출 결과 활성 257건, 사진(popfile) 100%·특징(specialMark) 100%·기존 keeper 서비스키로 동작. "중복" 근거도 재해석: lossInfo=**공식 신고자(공공)**, 자체글=**유저**로 모수가 달라 입양의 공공/유저 이원 구조와 대칭 → 중복이 아니라 **커버리지 보강 + 빈 게시판 콜드스타트 해결**.
  - **정체성** — 실종분실도 입양처럼 **"공공(lossInfo) + 유저(자체) → 실종 공고 단일 귀결"**. Phase 1은 공공 진입점만 먼저.
  - **PII 처리(필수)** — lossInfo엔 신고자 **실명(callName)+휴대폰(callTel)** 포함. 재공개는 개인정보보호법상 정보주체 동의 필요, **고지(告知)≠동의**라 노출 불가(위반 시 5년/5천만원). → 파이프라인 변환 단계에서 **callName·callTel 드롭**, DB 진입 자체 차단. 비-PII(사진·품종·색상·성별·나이·특징·지역·실종일)만 사용.
  - **인계 최대화** — keeper가 재회를 직접 못 시키므로 발견자를 공식 채널에 정확히 내려줌: ① 식별정보(사진·지역·실종일·특징) 강조 ② "국가동물보호정보시스템에서 확인" 아웃링크(`animal.go.kr/front/awtis/loss/lossList.do` — 공개·로그인 불필요, 건별 딥링크는 API에 고유 ID 없어 불가 → 게시판 레벨) ③ "봤어요 → 공식 발견신고" 안내.
  - **한계 인지** — 시딩 글은 원터치 재회 불가(공식 채널 경유). 1차 가치=실종 인지+게시판 생명력(마중물). 실제 재회 주력은 Phase 2 유저 글.
  - **발견 매칭(후속)** — 별도로, keeper가 **이미 동기화 중인 유기동물 공고**(`abandonment` 테이블)와 교차: "등록한 실종견과 비슷한 동물이 ○○보호소 보호 중" — 품종·지역·발견일·색상 기반. 외부 의존성 0. Phase 1 범위 밖.

## 후속 / 별도 트랙 (연계)

- **포스터 자동생성 + 인스타 확산** — [[05-poster-template-share]]. 실종의 **광역 확산 메커니즘** = 디지털화의 본질 가치. 가장 가치 큰 연계.
- **AI 포스터 폼채움** — [[05-ai-poster-prefill]]. 실종 등록 마찰 감소. 실종 폼 확정 직후 Phase 1.5 후보.
- **발견 매칭** — Q7 참조. 기존 `abandonment` 데이터 교차(외부 의존성 0).
- **알림(푸시)** — 앱 전반 알림 시스템은 이미 출시 구축됨([[project_notification_system]]). 실종 반경 푸시는 글 쌓인 뒤 별도.
- **지역/반경 필터** — 좌표 저장은 MVP, 필터·반경은 글 쌓인 뒤.

## 레퍼런스 BP 딥다이브 (해외 6개 서비스)

Petco Love Lost, PawBoost, PetFBI, Lost My Doggie, Nextdoor 조사. keeper 적용 기준:

| 항목      | 이식 (초기)                                             | 컷 / 나중                          |
| --------- | ------------------------------------------------------- | ---------------------------------- |
| 공고 필드 | 사진·위치·연락처 필수 + 종/품종/색상/실종일시/특징 선택 | 마이크로칩 DB연동, 보상금은 선택만 |
| 제보      | 댓글 (Nextdoor 모델)                                    | 전용 sighting 폼                   |
| 위치      | 지도 핀 + 좌표 (전문 서비스 공통 핵심)                  | 반경 슬라이더, 동선 추적           |
| 해결 상태 | "찾았어요" → 목록 정리                                  | 외부 DB 자동종료                   |
| 정렬·필터 | 종 + 지역 + 미해결                                      | 색상/품종 세분화                   |
| 알림      | 반경 푸시(FCM) — 검토                                   | SNS 자동공유, 전화/우편            |
| AI 매칭   | ❌ 과함 (PetFBI·PawBoost는 AI 없이 운영)                | 얼굴인식, Vision API               |
| 수익      | 무료/기부 (비영리 부합)                                 | 유료 구독·광고                     |

핵심 통찰: AI 얼굴인식은 1인운영 한계 초과로 컷. 지도 핀/좌표는 실종의 가장 차별적 UX.

## 백엔드 영향 (개요)

- PostType enum 에 `MISSING` 추가
- 신규 entity (post_missing): 개인입양 컬럼 재활용(animalType/specificType/age/weight/gender/images/특징) + 신규(실종 일시, 좌표 lat/lng, 해결 상태)
- 마이그레이션: keeper-backend Prisma(timestamp 1건). 구 keeper-api(MySQL 028) 표기는 폐기 — v2는 NestJS+Prisma. 영상 첨부는 [[04-video-upload]], 포스터 필드 충족 여부는 [[05-poster-template-share]] 와 연계.
