# 입양후기 게시판

- **상태**: 발산 초기 (검토 포인트만 — 기획 필요)
- **일자**: 2026-06-02

## 배경

[home-content-redesign](./home-content-redesign.md)에서 **"입양후기 슬라이더"가 강력 후보**로 나왔다 — 입양 성공 후기는 사회적 증명으로 입양 전환을 270% 높인다([genesysgrowth](https://genesysgrowth.com/blog/social-proof-conversion-stats-for-marketing-leaders)), Best Friends·ASPCA가 "Happy Tails"를 공고 다음 단독 섹션으로 배치.

그러나 keeper는 **표시(슬라이더)만 가능하고 후기를 생성하는 게시판·작성 흐름이 미기획**이라, 슬라이더만 만들면 채울 데이터가 없다. 별도 기획이 필요해 분리한다.

## 현황

| 영역        | 상태                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------- |
| 백엔드 조회 | `GET /adoption-reviews` (list/detail) 완성. 응답: id/images/petName/animalType/adoptionAt/content |
| 백엔드 작성 | **없음** (POST 미구현)                                                                            |
| 프론트      | 미구현                                                                                            |
| 데이터      | 생성 흐름 없어 비어 있음                                                                          |

## 핵심 검토 포인트 (기획 필요)

1. **작성 자격 / 트리거** — keeper는 입양 신청·완료 추적이 없다(보호소 직접 연락 방식). 누가 후기를 쓸 자격이 있나?
   - 옵션 A: **자발적 작성** (누구나 "입양했어요" 작성 + 검증 장치)
   - 옵션 B: **입양 추적 도입 후** 입양 확인자만 (알림·추적 인프라 필요, 큼)
2. **커뮤니티 "입양생활(LIFE)" 과의 중복** — 커뮤니티 LIFE 탭(현재 스캐폴드)도 "입양 후 일상 공유". 입양후기(adoption-review, 별도 엔티티) vs 입양생활(community LIFE, 커뮤니티 탭)의 개념을 **통합할지 분리할지** 확정 필요. (중복 방치 시 사용자 혼란 + 데이터 분산)
3. **검증 / 신뢰** — 비영리 신뢰가 핵심. 가짜 후기 방지 정책?
