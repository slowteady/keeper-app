# 백로그: 공지사항 (발행 + 공지함 + 홈 띠배너)

작성일: 2026-06-11
상태: 아이디어 확정·스펙 상세화 대기 (P1)

---

## 배경 / 왜

- keeper는 1인/소수 운영이라 **사용자에게 한마디 할 채널**이 필요하다 — 업데이트 안내·정책 변경·이벤트·점검 예고 등.
- 현재 공지 노출 수단이 없음. `app_config`/`/bootstrap` 인프라는 있으나 공지 연결 0.
- 안 만들면: 운영 커뮤니케이션을 푸시/외부(인스타 등)에만 의존 → 도달률 낮고 "놓친 공지 어디서 보나" 이탈 지점 발생.

## 전략 축

1. **중요도별 채널 분리** — 평소 공지(공지함) / 중요 공지(홈 띠배너) / 비상(게이트)을 섞지 않는다. 섞으면 광고로 인식돼 스킵됨(BP).
2. **저비용 운영** — 1인 운영에서 유지 가능하게. 홈 띠배너는 기존 `/bootstrap` 인프라 재활용, 모더레이션·정산 무거운 건 없음.

## 선행 조건

- **P0-5 강제업뎃 게이트(`/bootstrap`)** — 홈 띠배너용 "중요 공지 1건" 필드를 여기 얹음. 게이트 작업과 같은 엔드포인트.
- 공지함 목록은 별도 list API (게이트와 독립).

## 핵심 가설

- 공지를 **프로모 배너와 분리**(공지함 + 띠배너)하면 도달률↑·신뢰 훼손 방지. (검증: 출시 후 공지 클릭률·공지함 진입률)
- 중요 공지 1건만 홈 띠배너로 띄우고 0건이면 영역 제거 → 홈의 공고 탐색 흐름을 안 해친다.

## 데이터 모델 (초안)

- `notice` entity (초안): `id / title / content / imageUrl?(상세 이미지) / isImportant(띠배너 노출 여부) / startAt / endAt? / createdAt`
- `/bootstrap` 응답에 `importantNotice?: { id, title }` 1건 추가 (띠배너용, 가장 최근 isImportant 공지)
- 공지함 목록: `GET /notices` (페이지네이션)
- 결정 아님. 발산 단계 초안.

## 로드맵 (Phase 단위)

### Phase 0: 선행

- P0-5 게이트(`/bootstrap`) 완료 → `importantNotice` 필드 얹기

### Phase 1: MVP

- 백엔드 공지 CRUD (운영자 발행) + 상세·이미지
- 공지함 탭 (목록 → 상세). 진입점: 프로필/설정 메뉴 (탭바 슬롯 안 씀)
- 홈 상단 띠배너 (중요 공지 1건, 0건이면 영역 제거, 탭 → 상세)

### Phase 2: (선택, 후속)

- 읽음 처리 / 안 읽은 공지 배지
- 공지 카테고리(점검·이벤트·정책) 분류

## 레퍼런스 BP

- [카카오뱅크 공지사항](https://m.kakaobank.com/Notices/view/18554) — 긴급·점검=진입 팝업, 일반=공지사항 탭, 홈 배너엔 프로모만 → keeper도 공지/프로모 채널 분리
- [토스 모달 패턴](https://medium.com/@beomsu/%ED%86%A0%EC%8A%A4%EB%8A%94-%EB%AA%A8%EB%8B%AC%EC%9D%84-%EC%96%B8%EC%A0%9C-%EC%96%B4%EB%96%BB%EA%B2%8C-%EB%9D%84%EC%9A%B8%EA%B9%8C-841e97dda1eb) — 공지=인박스 탭, 긴급=전면 Alert. 긴급도에 따라 컴포넌트 분리 → keeper 중요도별 채널 근거
- [당근마켓 UX 분석](https://brunch.co.kr/@plusx/70) — 시스템 공지를 알림함(벨)으로 분리, 홈 띠배너 없음 → "홈은 핵심 흐름" 정합
- [NN/g - Popups](https://www.nngroup.com/articles/popups/) — 진입 팝업은 법적 동의·서비스 중단 등 중대 정보에만. 남발=이탈 → keeper 긴급 팝업 컷 근거
- [Baymard - Homepage Carousel](https://baymard.com/blog/homepage-carousel) — 슬라이드 ≤5, 84%가 첫 슬라이드만 상호작용 → 공지를 캐러셀에 섞지 않는 근거
- [WCAG 2.2.2 - Pause/Stop/Hide](https://wcag.dock.codes/documentation/wcag222/) — 자동전환 콘텐츠는 일시정지 컨트롤 의무 (캐러셀 쓸 경우)

## 컷한 옵션 (사유 명시)

- **공지를 홈 프로모 배너 캐러셀에 통합** — 컷. BP 충돌: 사용자가 캐러셀을 광고 슬롯으로 인식해 스킵, 정작 공지를 놓침(토스·카뱅·당근 모두 분리). 기존 `03-home-content-redesign.md`의 "배너 1줄 통합" 결정을 이 BP 조사로 뒤집음.
- **긴급 진입 팝업(앱 켜면 모달)** — 컷(보류). 남발 시 이탈(71%가 과한 알림에 앱 삭제, NN/g). 비상 안내는 P0-5 게이트(점검 화면)가 이미 커버하므로 별도 팝업 불필요. 정말 필요해지면 "세션 1회 + 다시 보지 않기" 엄격 제약으로 후속 검토.
- **자동전환 캐러셀** — 컷. 공지는 1건 띠배너로 충분. 캐러셀 쓰면 ≤5개·자동전환 off·WCAG 일시정지 부담만 늘어남.
