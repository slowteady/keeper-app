# 백로그: 신고 처리 (운영자 모더레이션)

작성일: 2026-06-19
상태: 아이디어 확정 (admin-console 후속 1순위 슬라이스). BP 조사 완료.
관련: `admin-console.md`(셸·후속 슬라이스) · `00-notification-system.md`(통지 의존) · `release-plan.md` §1(신고·차단 P0) · product-roadmap F-01(사용자측 신고후속) · 정보통신망법 §44조의2

## 배경 / 왜

- 사용자 신고 접수(post_report/comment_report)는 **쌓이기만 하고 운영자 처리 화면이 0**. UGC(개인입양·커뮤니티) 받는 이상 처리 수단은 법적 의무.
- 정보통신망법 §44조의2 = **규모·비영리 예외 없음.** 권리침해 소명 신고 시 임시조치(블라인드)·양 당사자 통지·약관 절차 명기 의무.

## 전략 축

1. **임시조치 우선** — 삭제(영구) 아닌 블라인드(접근차단, isHidden, 최대 30일)가 §44-2 면책 요건. 기존 `post.isHidden`·`ReportAction(HIDE/DELETE/BAN/NONE)`·`handledAt/handledAction` 재활용.
2. **최소 운영 워크플로우** — AI 사전필터(OpenAI, 기존) → 운영자 단일 큐 수동 검토 → 결과 통지(알림 후). 1인 감당 가능선.
3. **통지는 인앱 알림함이 1차** — 종 아이콘 → 알림센터(`00-notification-system.md` Notification 테이블). 신고 통지도 이 알림함에 쌓임. push는 보조.

## 이번 슬라이스 스코프

### 포함 (운영자 신고 큐)

- **신고 큐(admin 콘솔)** — 신고된 글/댓글을 **집계 단위**(같은 대상 다중신고 묶음 + 신고수 + 사유 요약 + 미처리/완료)로 표시. (Reddit/Blind 패턴)
- **임시조치 액션** — 블라인드(isHidden)/삭제/기각 → `handledAt`·`handledAction` 일괄 기록.
- **상태** — PENDING(handledAt null) → RESOLVED. (1인이라 IN_REVIEW 생략)

### 연기·재활용

- **통지**(비대칭: 신고자=결과만 / 게시자=사유+이의) → **알림 시스템(B-2) 의존**. 이번엔 이벤트 인터페이스만, 알림 완성 시 알림함 항목으로 연결.
- **이의제기** → 신규 X. 기존 **1:1 문의(type=APPEAL) 재활용**. (당근 모델)
- **반복 위반자 BAN** → 후속(유저 관리 슬라이스 + user violation 컬럼). 자동 BAN은 인간 확인 필요.
- **다중신고 임계 자동 블라인드** → 후속 옵션. 이번엔 수동 검토만.
- **F-01 사용자측 신고후속**(본인 피드 숨김·"신고됨" 표시) → 별도 슬라이스(keeper-app), 병렬 가능.

## 백엔드 영향 (keeper-backend)

- 신규 admin API(`@Roles(ADMIN)`): `GET /admin/reports`(집계 큐) · `GET /admin/reports/:type/:id`(대상+신고들 상세) · `POST /admin/reports/:type/:id/handle {action}`(처리).
- 마이그레이션: **`PostComment.isHidden` 추가**(댓글 블라인드용. Post엔 이미 있음).
- 신고 집계 = 대상별 group by(컬럼 불필요). 통지 이벤트 = 인터페이스 자리(no-op, 알림 의존).

## 프론트

- **admin 콘솔(keeper-admin)**: 신고 큐 페이지(Refine resource "reports" + shadcn 테이블) + 상세(콘텐츠 미리보기 + 신고 목록 + 블라인드/삭제/기각).

## 정책

- **terms.md(keeper-web)**: §44-2 임시조치 절차 명기 — 블라인드(30일 이내)·양 당사자 통지·이의신청 창구(1:1 문의). 법상 최소 요건(약관 명시 의무).

## 컷한 옵션 (사유)

| 옵션                        | 사유                                                                               |
| --------------------------- | ---------------------------------------------------------------------------------- |
| 통지를 이번 슬라이스에 포함 | 알림 시스템(인앱 알림함) 미구축. 통지는 알림 항목으로 들어가야 함 → 알림 직후 연결 |
| 전용 이의제기 기능          | 1:1 문의(APPEAL)로 충분(당근 모델). 신규 빌드 불필요                               |
| 자동 임계 블라인드          | 1인 운영은 수동 검토 우선. 어뷰징·오판 리스크                                      |
| 자동 BAN                    | 인간 최종 확인 권장(Discord enforcement ladder). 유저 관리 슬라이스로              |
| IN_REVIEW 상태              | 1인 운영엔 과함. PENDING→RESOLVED 직행                                             |

## 의존 / 순서

- **완전 컴플라이언스 = 통지 필요 = 알림 시스템 필요.** 이번(큐+블라인드+약관) → **알림 시스템(B-2)** → 통지 연결. 그래서 신고처리 다음에 알림을 바로 하는 게 자연스러움.
