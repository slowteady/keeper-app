# 개인입양 상세 페이지 재설계

작성일: 2026-06-12
대상 화면: 커뮤니티 > 개인입양 상세 (`src/app/(untabs)/community/[id]/index.tsx`)

## 배경 / 문제

현재 상세 페이지는 작성 폼에서 입력받는 **성격·생활습관 데이터를 전혀 표시하지 않는다.** mapper(`convertToAdoptDetailBehaviorData`)는 구현돼 있으나 어디서도 호출되지 않는 dead code 상태로, 사용자가 입력한 배변훈련·짖음·활동량·아이/개/고양이 호환 정보가 버려진다. 그 외에도 정보 블록 순서와 CTA 위치가 입양 의사결정 흐름과 어긋난다.

## 목표

- 버려지던 성격·생활 데이터를 상세에 노출 (P0)
- 본문 블록 순서를 입양 의사결정 흐름에 맞게 재배치
- 문의 CTA를 주 액션으로 부각 (하단 통합바)
- 선택 입력 항목의 빈 값 처리 일관화

## Non-Goals

- 상단 구성(작성자 → 제목 → 이미지 → 칩) 변경 — 개인이 쓴 "글" 성격을 유지하므로 현행 그대로 둔다. (이미지 우선 배치는 상품 카탈로그 관점이라 채택하지 않음)
- 기본정보(나이·성별·크기) 위치 변경 — 소개글 뒤 현행 유지
- 작성 폼 변경

## 렌더 순서 (확정)

```
① 작성자 · 시간              ♡  ↑  ⋯       현행 유지
② 제목                                      현행 유지
③ 이미지 캐러셀                              현행 유지
④ [분류] [보호유형] 칩                        현행 유지
──────────────────────────────
⑤ 소개                                       현행 유지
──────────────────────────────
⑥ 기본정보   나이 · 성별 · 크기/몸무게         현행 위치(소개 뒤)
──────────────────────────────
⑦ 성격·생활 (2열 라벨-값)            ★신규
──────────────────────────────
⑧ 건강   ✓중성화 ✓백신 ?검진 + 아파요
──────────────────────────────
⑨ 🔗 관련 링크                       (있을 때만)
──────────────────────────────
⑩ 💬 댓글수  ♡ 좋아요  👁 조회         통계
──────────────────────────────
⑪ 댓글 목록
──────────────────────────────
   하단 고정 통합바: [ 📞 문의 ] [ 댓글을 입력하세요… ↑ ]
```

현재 대비 변경:

- 성격·생활 섹션(⑦) 신규 추가
- 통계(⑩)를 문의 버튼 앞 → 댓글 직전으로 이동
- 문의 CTA를 인라인 버튼 → 하단 통합바로 통합
- 건강(⑧)을 상태칩 + 아파요 한 덩어리로 정리

### 성격·생활(⑦) 배치 근거

Petfinder 상세는 `소개(About) → 성격(Characteristics) → 건강(Health)` 순. 입양 의사결정이 "어떤 성격인지(같이 살 핏) → 돌봄 부담(건강)" 흐름이라 성격을 건강 앞에 둔다.

표시 형태는 2열 라벨-값 (Petfinder Characteristics 방식):

```
배변훈련      완료
혼자 있기     가능
짖음          적음
활동량        많음
아이와        좋아요
강아지와      좋아요
고양이와      보통
```

데이터 소스는 기존 `convertToAdoptDetailBehaviorData`가 반환하는 `BehaviorItem[] = { label, value }[]`. 파이프라인이 이미 완성돼 있어 렌더 컴포넌트만 추가하면 된다.

## 빈 값 처리 방침

원칙: **핵심 사실은 "모름"도 노출(입양 판단 정보), 부가 설명은 입력된 것만 노출.**

| 섹션                        | 성격      | 빈 값 처리                                       |
| --------------------------- | --------- | ------------------------------------------------ |
| 기본정보(나이·성별·크기)    | 핵심 사실 | 미입력도 "미상" 표시 (현행 유지)                 |
| 건강 상태(중성화·백신·검진) | 핵심 사실 | 미입력 "?" 아이콘 (현행 유지)                    |
| 아파요(health)              | 부가      | 빈 값이면 항목 숨김                              |
| 성격·생활 7항목             | 부가      | 입력된 항목만 2열 표시, 전부 비면 섹션 통째 숨김 |
| 관련 링크                   | 부가      | 빈 값이면 숨김 (현행)                            |

- 성격 섹션 표시 조건: `behaviorItems.length > 0`
- 부가 섹션이 모두 비면 본문은 `소개 → 기본정보 → 건강 → 통계`로 자연 축소
- 연속 divider 겹침은 각 섹션의 조건부 렌더로 방지

## 하단 통합바 (당근형)

문의가 주 액션, 댓글 입력이 보조. 좌측 문의 버튼 + 댓글 입력 필드로 묶는다.

```
┌────────────────────────────────────┐
│ [ 📞 문의 ] [ 댓글을 입력하세요…  ↑] │
└────────────────────────────────────┘
   📞 문의 → 문의 바텀시트(연락처 + 안전고지) 오픈
```

- 연락처 없는 글(`hasContact === false`)이면 문의 버튼 숨기고 댓글 입력만 풀너비 (기존 `hasContact` 로직 재사용)
- 댓글 수정/답글 모드 배너는 통합바 위에 그대로 표시 (현행 유지)
- 키보드 대응(KeyboardStickyView)·safe-area padding 현행 유지

## 구현 관점 (FSD)

- **신규**: 성격·생활 렌더 위젯 (예: `BehaviorSection`). 기존 `convertToAdoptDetailBehaviorData` 연결만 하면 됨 — 데이터 파이프는 완성 상태
- **수정**: 상세 `index.tsx` 렌더 순서(통계 위치, 성격 섹션 삽입), 하단 `CommentFormInput`에 문의 버튼 통합
- **재사용**: 기본정보·건강은 기존 `adopt-detail-info-section` 그대로
