# /qa — 구현 검증

`/be` `/fe` 가 끝난 기능을 명세 정합성 + 회귀 + 자동 테스트 + MCP 시뮬 검수
로 전체 검증. 산출물은 `docs/qa/<feature>.md`.

## 분리 원칙 — 메인 vs 서브에이전트

기준 한 줄: **사용자가 화면을 봐야 하는가**.

- **메인이 직접** — MCP 시뮬 검수 (시각 회귀·UX 어색함), 사용자 종합 보고,
  산출물 작성
- **서브 위임** — `qa-auditor` (위험 분석 + 명세 정합성 + 자동 테스트 실행)

## 절차 (순서대로)

### 1. 입력 확정

어느 기능을 QA 할지 확인. PRD/design/spec 모두 있는지 확인. 없으면 누락된
선행 스킬 안내.

### 2. qa-auditor 위임 — 위험·명세·자동 테스트

```
Agent(subagent_type="qa-auditor",
  description="구현 검증",
  prompt="기능: <feature-name>

  대상:
  - docs/prd/<feature>.md
  - docs/design/<feature>.md
  - docs/spec/<feature>.md
  - 최근 변경 (git log / diff)

  요청: 위험 기반 분석 + 명세 정합성 + 자동 테스트 실행. 표만, raw 인용 X.")
```

받은 결과 — 위험 모듈 / 정합성 표 / 테스트 요약 / 발견 사항 표 (P0~P2).

### 3. MCP 시뮬 검수

서브가 못 잡는 시각·UX 이슈를 메인이 직접 확인.

- `.maestro/flows-<platform>/<feature>.yaml` 실행 (있는 경우) 또는 핵심 흐름
  Maestro MCP 로 수동 재현
- 화면 raw 직접 보고 — 어색함 / 시각 회귀 / 인터랙션 이슈 / 빈 상태 / 에러 상태
- iOS / Android 둘 다 확인 가치 (변경 영역에 따라)
- **로그인 필요 흐름은 로그인 화면의 `[DEV] 개발자 로그인` 버튼 사용** — 소셜 로그인 (Kakao/Naver/...) 은 시뮬에서 OAuth 핸드셰이크 불가
- fix 후 검증도 동일 — 사용자에게 "확인 부탁" 떠넘기지 않고 MCP 로 직접 재현 후 결과 보고

자동 테스트 PASS 라도 UX 회귀는 여기서만 잡힘.

### 4. 발견 사항 종합

서브 결과(P0~P2) + MCP 검수 결과 통합.

- **P0** — 명세 누락 / 회귀 / 검증 실패 / 보안·데이터 무결성
- **P1** — UX 어색함 / 미세 정합성 / 비기능 영향
- **P2** — 개선 여지 / 컨벤션 미세 위반

### 5. 사용자 보고

P0 는 즉시 사용자에게 알리고 처리 결정. P1/P2 는 산출물에 정리, 사용자에게
요약만.

P0 미해결 상태로 QA 완료 처리 금지.

### 6. 산출물 작성

`docs/qa/<feature>.md` 신규. 템플릿은 `references/qa-template.md` 참조.

기능별 QA 이력 누적 — 같은 기능 재검증 시 이전 QA 결과 위에 갱신 (날짜·상태
추가).

## 안티패턴

- **자동 테스트 통과 = QA 완료 단정**: tsc/jest/eslint 통과해도 UX 회귀·명세
  누락 가능. MCP 시뮬 + 명세 정합성 둘 다 확인해야.
- **MCP 검수 생략**: 시각·UX 이슈는 코드 검증만으로 못 잡음.
- **raw 결과 메인에 가져오기**: 서브가 요약. 메인 컨텍스트 보호.
- **심각도 등급 없이 나열**: 사용자가 어디부터 손대야 할지 모름. P0/P1/P2
  분류 강제.
- **P0 미해결 채로 QA 완료**: P0 는 즉시 fix → 재검증. 잔존 P0 가 있으면 QA
  실패로 처리.
- **PRD/design/spec 없이 시작**: 명세가 없으면 정합성 비교 불가. 선행 스킬
  결과를 입력으로 받는다.
